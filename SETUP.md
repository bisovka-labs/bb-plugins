# Сетап bb как у Евгения Бисовки

Это инструкция для агента (Claude Code, Codex или агент внутри bb). Человеку достаточно сказать
агенту:

```text
Прочитай https://raw.githubusercontent.com/bisovka-labs/bb-plugins/main/SETUP.md и настрой мне bb по этой инструкции. Сначала задай вопросы из раздела «Перед началом», потом иди по шагам и останавливайся там, где нужен я.
```

Что получится:

1. мои плагины для bb (кнопки, телефонный интерфейс, Safari для агентов, тудулист, диктовка);
2. чужие плагины, которыми я реально пользуюсь каждый день;
3. голосовой ввод на русском, который работает на самом Маке;
4. bb открывается с телефона и других твоих устройств через Tailscale, и больше ни у кого к нему
   доступа нет, даже через сервис bb;
5. всё это не ломается, если ты сидишь под VPN.

Software Factory и мои личные сервисы сюда не входят.

---

## Правила для агента

- Работаешь на Маке, где запущен или будет запущен сервер bb (macOS). Все команды отсюда.
- Шаги с пометкой **[человек]** делает человек: входы в аккаунты, разрешения macOS, телефон,
  админка Tailscale. Дойдя до такого шага, остановись, объясни простыми словами, что нажать, и жди.
- Ничего не удаляй и не выключай из того, что у человека уже настроено, без его «да».
- Сторонний плагин запускается на Маке с полными правами. Перед установкой покажи человеку список
  и получи согласие. Флаг `--yes` у `bb plugin install` ставь только после этого согласия.
- После каждого раздела проверь результат командой из пункта «Проверка». Не прошло — разберись
  или скажи человеку, что именно не вышло. Не пиши «готово» без проверки.
- В конце дай человеку короткий отчёт: что поставлено, адрес bb для телефона, что не получилось.

## Перед началом: спроси человека

1. **Где ты физически и сидишь ли под VPN?** Каким клиентом на Маке и на телефоне (Happ, Hiddify,
   v2RayTun, Streisand, Amnezia, Outline, Mullvad, Clash Verge и т.п.), он заворачивает весь трафик
   или только заблокированное? От ответа зависит раздел 5.
2. **Нужен ли bb с телефона, планшета или второго ноутбука?** Если нет, разделы 4 и 5 пропусти.
3. **Есть ли у тебя iPhone с кнопкой Action и хочешь ли запускать агента голосом с неё?**
   Если да, в разделе 4 ставь шлюз диктовки.
4. **Есть ли складной или широкий сенсорный экран (iPad, раскрытый складной телефон), с которого
   ты открываешь bb?** Если да, ставь `duo-layout`.

## 0. Проверка, что bb на месте

```bash
bb --version
bb status
```

Нет команды `bb` → **[человек]** скачивает и ставит bb с https://getbb.app, открывает его один раз,
входит. Потом продолжай.

Мак с bb должен не засыпать, иначе телефон его не достанет:

```bash
bb keep-awake enable
bb keep-awake status
```

## 4. Доступ с телефона через Tailscale

### Зачем так, а не через bb connect

У bb есть встроенный доступ извне (bb connect, адрес вида `имя.getbb.app`). Это удобно, но тогда до
твоего bb, а значит до терминала и всех файлов Мака, можно достучаться через чужой сервис, и вся
защита держится на одном аккаунте. Я сделал по-другому:

```
твои устройства (телефон, планшет, второй ноутбук)
   │ Tailscale: зашифрованная частная сеть только из твоих устройств
   ▼
tailscale serve https :17443 ──► Caddy (шлюз) ──► bb на Маке (127.0.0.1)
                                  пускает, только если Tailscale подтвердил,
                                  что запрос пришёл с устройства под ТВОИМ логином
```

Снаружи bb не видно вообще. Если в твоей сети Tailscale есть серверы или устройства других людей,
они тоже получают отказ: Tailscale ставит подпись с логином только на запросы с твоих устройств и
вырезает поддельную.

### 4.1 Tailscale на Маке **[человек]**

1. Скачать Tailscale для macOS: https://tailscale.com/download/mac (если сайт не открывается, с
   включённым VPN; подробности в разделе 5). Установить, открыть, войти (Google, GitHub, Apple или
   почта). Этот логин и станет единственным, кого пустит шлюз.
2. В админке https://login.tailscale.com/admin/dns включить **MagicDNS** и **HTTPS Certificates**.
3. В https://login.tailscale.com/admin/machines у Мака: «⋯» → **Disable key expiry**. Иначе через
   180 дней Мак выпадет из сети и телефон его потеряет.

Агент проверяет: `/Applications/Tailscale.app/Contents/MacOS/Tailscale status` показывает Мак,
без `Logged out`.

### 4.2 Шлюз

```bash
command -v caddy || brew install caddy
git clone https://github.com/bisovka-labs/bb-plugins.git ~/.bb-setup/bb-plugins 2>/dev/null \
  || git -C ~/.bb-setup/bb-plugins pull
cd ~/.bb-setup/bb-plugins
setup/private-access.sh              # если «да» на вопрос 3: setup/private-access.sh --dictation
```

Скрипт:

- берёт твой логин из Tailscale и порт bb из `~/.bb/bb-app-runtime.json`;
- пишет шлюз `~/.config/bb-guard/Caddyfile` и запускает его как LaunchAgent `local.bb-guard`;
- ставит сторож `local.bb-guard.tailscale-watchdog`: раз в 2 минуты поднимает Tailscale, если тот
  остановился (так бывает после его автообновления);
- публикует bb в tailnet: `https://<имя-мака>.<tailnet>.ts.net:17443`;
- с `--dictation` открывает на `:18080` только маршрут диктовки (он защищён своим токеном);
- кладёт `~/.local/bin/ts-share`, см. 4.5.

Если `tailscale serve` пишет, что HTTPS не включён, вернись к 4.1 пункт 2.
Посмотреть состояние: `setup/private-access.sh --check`. Убрать всё: `setup/private-access.sh --undo`.

**Проверка:** скрипт печатает `HTTP 200`. Логи шлюза: `~/Library/Logs/bb-guard/app-gate.log`.

### 4.3 Политика tailnet (если в сети не только твои устройства)

Если в Tailscale только твои Мак и телефон, ничего не трогай. Если там есть серверы (VPS) или
устройства других людей, **[человек]** открывает https://login.tailscale.com/admin/acls, сохраняет
старую политику себе, вставляет пример из `setup/tailnet-policy.example.hujson` и вешает на
серверы тег `tag:server`. В примере ещё убран Funnel, чтобы никакой агент не выставил bb в
интернет.

### 4.4 Телефон и планшет **[человек]**

1. Поставить приложение Tailscale (App Store или Google Play), войти **тем же** логином, включить.
2. Поставить приложение bb. В нём: свайп от левого края → шестерёнка внизу → в самом низу
   **This device** → **Servers** → **+** → Server URL: адрес из 4.2, Label: «Мак» → **Connect**.
3. Адрес обязательно с `https://`.

Второй Мак как клиент: в приложении bb меню **Window → Server → Add Server…**, тот же адрес.

**Проверка:** с телефона открывается список тредов; в `app-gate.log` появились запросы.

### 4.5 Агентам: показывать локальные сайты через ts-share

Когда агент поднимает сайт или прототип на Маке, вместо `bb connect expose` он публикует его только
для твоих устройств:

```bash
ts-share 3000        # → https://<имя-мака>.<tailnet>.ts.net:3000
ts-share off 3000
ts-share list
```

Допиши это правило в инструкции, которые bb подставляет всем агентам. Сначала прочитай текущие,
ничего не затирай:

```bash
bb instructions get
bb instructions set "$(bb instructions get)
Чтобы показать мне локальный сервер, вместо bb connect expose запускай ts-share <порт> (сервер должен слушать 127.0.0.1:<порт>), давай адрес markdown-ссылкой; ts-share off <порт> убирает. bb для меня открывается по адресу https://<имя-мака>.<tailnet>.ts.net:17443."
```

### 4.6 Выключить bb connect (по желанию)

Только когда телефон уже открывает bb через Tailscale и человек сказал «да»:

```bash
bb connect off
```

Вернуть: `bb connect on`.

## 5. Если ты сидишь под VPN (или ты в России)

Сначала пойми, что зачем:

- **VPN** у тебя для выхода в заблокированный интернет: Claude, ChatGPT, Instagram и т.д. На Маке
  он нужен, чтобы агенты в bb вообще работали.
- **Tailscale** тоже VPN, но для другого: он соединяет твои устройства между собой. Через него
  телефон достаёт до Мака. В интернет через него ничего не ходит, пока ты сам не включишь exit node.

Конфликтуют они в двух местах.

### 5.1 На Маке: VPN не должен забирать трафик Tailscale

macOS держит оба одновременно, но клиент VPN в режиме «весь трафик через туннель» (TUN, «Системный
VPN», «Full tunnel») может завернуть в себя адреса Tailscale. Тогда телефон перестаёт видеть Мак,
хотя оба «подключены». Агент делает так:

1. Спроси, какой клиент. Найди в нём правила маршрутизации или исключения и добавь в «напрямую»
   (direct, bypass):
   - сети Tailscale: IPv4 диапазон CGNAT (начинается со `100.64`, маска `/10`, см.
     https://tailscale.com/kb/1015/100.x-addresses) и IPv6 `fd7a:115c:a1e0::/48`;
   - домены `*.ts.net` (имена твоих устройств).
2. Если в клиенте есть раздельное туннелирование по приложениям (Mullvad, Amnezia, часть платных
   VPN), исключи приложение Tailscale. У меня это ломалось после обновления Tailscale: его системное
   расширение переезжает в новую папку, и старое исключение перестаёт работать. После каждого
   обновления Tailscale проверяй, что исключение указывает на актуальный путь:
   `ls -d /Library/SystemExtensions/*/io.tailscale.ipn.macsys.network-extension.systemextension`.
3. Если клиент умеет режим «системный прокси» вместо TUN, это тоже вариант: прокси Tailscale не
   трогает. Но тогда в исключения прокси всё равно добавь `*.ts.net` и тот же диапазон CGNAT.
4. Не включай на Маке exit node Tailscale одновременно с VPN.

**Проверка:**

```bash
TS=/Applications/Tailscale.app/Contents/MacOS/Tailscale
$TS status            # телефон в списке, без ошибок
$TS netcheck          # видно ближайшие DERP-серверы с задержками
$TS ping <имя-телефона>
```

`ping` должен ответить `via DERP(…)` или `via <ip>:<порт>` с адресом твоего провайдера. Если там
адрес сервера твоего VPN или ping не отвечает, VPN всё ещё забирает Tailscale: вернись к пункту 1.

### 5.2 Вход в Tailscale из России

У части российских провайдеров сайт входа Tailscale и скачивание не открываются, а сами соединения
WireGuard (на нём построен Tailscale) периодически режут, где-то сильнее, где-то слабее. Агент
проверяет, а не гадает:

```bash
curl -sS -o /dev/null -w '%{http_code}\n' -m 10 https://controlplane.tailscale.com/key?v=71
curl -sS -o /dev/null -w '%{http_code}\n' -m 10 https://login.tailscale.com/
```

- Отвечает (любой код, кроме `000`) → всё нормально.
- `000` или 451 без VPN → **[человек]** скачивает Tailscale и входит в аккаунт с включённым VPN.
  После входа устройства продолжают работать на сохранённых ключах. Поэтому и нужен пункт 4.1.3
  (Disable key expiry): иначе раз в полгода придётся входить заново.
- Прямое соединение не проходит → Tailscale сам идёт через свои ретрансляторы (DERP) по обычному
  HTTPS на 443. Медленнее, но работает. Это и показывает `netcheck`.

### 5.3 На телефоне: одновременно работает только один VPN

iPhone и Android держат только один активный VPN, а Tailscale для них тоже VPN. Включил свой VPN,
Tailscale выключился, и наоборот. Варианты, от простого к удобному:

1. **Переключать.** Для bb на телефоне нужен только Tailscale: агенты работают на Маке, а Мак сам
   ходит в интернет через свой VPN. Открываешь bb, включаешь Tailscale. Нужен Instagram, включаешь
   свой VPN. На iPhone переключение в Настройки → VPN или в самих приложениях.
2. **Один VPN на всё через exit node.** Если у тебя есть свой сервер за границей (тот же VPS, на
   котором стоит твой VPN), поставь на него Tailscale и сделай его exit node
   (`tailscale set --advertise-exit-node` на сервере, разрешить в админке). Тогда на телефоне
   включён только Tailscale: bb открывается, а интернет идёт через твой сервер. Работает, только
   если Tailscale стабильно подключается в твоей сети (пункт 5.2). Если нет, оставайся на варианте 1.
3. **Мобильный интернет режет Tailscale.** Бывает у отдельных мобильных операторов. Тогда bb с
   телефона открывай по Wi-Fi или через bb connect (раздел 4.6, он работает поверх обычного HTTPS),
   понимая, что это доступ через сервис bb.

### 5.4 Остальное, что ходит в интернет

- Модель GigaAM (раздел 3) и плагины с GitHub качаются один раз. Если установка зависла, повтори
  с включённым VPN.
- Сервер bb на Маке и агенты используют сеть Мака, то есть твой VPN. Отдельно для bb ничего
  настраивать не надо.
